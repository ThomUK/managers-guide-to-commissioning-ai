Glossary

Each term has one sentence in plain English and, where it helps, one more sentence of precision.

LLM (large language model)
A computer program that produces text by repeatedly predicting the next small piece of text. What it learned in training is held as billions of numbers.
Token
A small piece of text, often a word or part of a word, that a model reads or writes as one unit. As a rule of thumb, a token is about three-quarters of an English word.
Context window
The amount of text a model can take into account at once, counted in tokens. It holds the instructions, the conversation so far and any documents supplied.
Training
The one-off process, done by the model’s maker, of setting the model’s numbers by showing it very large amounts of text.
Inference
Using a trained model to produce an answer. Every prompt you send is inference; it does not change the model.
Parameter (weight)
One of the numbers inside a model that were set during training. “27B” means 27 billion parameters.
Open weights
A model whose file of numbers is published, so that anyone can download it and run it on their own hardware. Licence terms still apply.
API
A way for one piece of software to use another; here, your software sending text to a vendor’s model and getting text back. API use is usually paid for per token.
GPU
A processor that does a very large number of simple calculations at the same time, which is what running a model needs. The letters stand for graphics processing unit, after its original use.
CPU
The general-purpose processor in every computer, with a small number of powerful cores. It can run a model, but usually far more slowly than a GPU.
Memory (RAM / GPU memory)
The fast working storage a model must be loaded into before it can run. RAM serves the CPU and GPU memory serves the GPU; some machines share one pool, called unified memory.
Memory bandwidth
How quickly data can be moved from memory to the processor, measured in gigabytes per second.
Prompt processing (prefill)
The first phase of a response, in which the model reads the whole prompt in one go. Engineers call this prefill.
Token generation (decode)
The second phase of a response, in which the model writes the answer one token at a time. Engineers call this decode.
Time to first token
The wait between sending a prompt and seeing the first piece of the answer.
Tokens per second
How fast a model writes its answer once it has started.
KV cache
The model’s working notes on the text it has already read, kept so that it does not have to re-read it for every new token. It takes memory and grows with the length of the conversation.
Prompt caching
A provider keeping its notes on a prompt it has seen before, so that it can reuse them. Cached input is usually priced lower.
Agent
An AI system that uses a model in a loop to carry out a task by using tools, rather than only replying with text.
Tool
Something a model has been connected to that lets it fetch information or take an action, such as searching files or sending an email.
Permission
A setting that controls whether an agent may use a tool freely, must ask first, or may not use it at all.
RAG (retrieval-augmented generation)
Finding the most relevant passages in your documents and giving them to the model along with the question.
Fine-tuning
Further training of an existing model on your own examples, which changes its numbers. It suits changes of behaviour and style better than adding facts.
Dense model
A model that uses all of its parameters for every token.
MoE (mixture of experts)
A model built from many specialist groups of parameters, of which only a few are used for each token.
Active parameters
The number of parameters an MoE model actually uses for each token. Active parameters decide speed; total parameters decide whether the model fits in memory.
Quantisation
Storing each of a model’s numbers less precisely, so that the model is smaller and faster at a small cost in quality.
Bit
The smallest unit of computer storage: one yes-or-no. A number stored in 16 bits is more precise than one stored in 4.
Batching (concurrency)
Serving several users’ requests in the same pass through the model. Each user slows a little while total output rises a lot.
