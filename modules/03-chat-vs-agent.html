A chat window vs. an agentic system

You need this if someone asks you to approve an AI “agent”, or an AI tool that can take actions.

The key idea

A chat window can only say things. An agent can do things, and what it is able to do is set by the tools and permissions you give it.

What a tool is

On its own, a model can only produce text. A tool is anything the model has been connected to that lets it fetch information or take an action: search a database, read a file, send an email. The model asks for a tool to be used by writing a request in an agreed format. The software around the model carries out the request and passes the result back.

A tool that only reads, such as looking up an invoice, is very different from one that acts, such as sending an email or making a payment. Reading can expose information. Acting changes things, and some changes cannot be undone.

The loop

An agent is a model running in a loop. It thinks about what to do next, acts by using a tool, observes the result, then thinks again. It repeats this until the task is done or it is stopped.

This is why an agent takes longer, and uses many more tokens, than a single answer. Every turn of the loop is another full request to the model, and each one carries the growing record of everything that has happened so far.

Same model, different connections

The model in the chat window and the model in the agent can be exactly the same one. The difference is what it is connected to and what it is allowed to do. A permission is a gate on each tool: open, ask first, or locked. Those gates, far more than how capable the model is, decide what can go wrong.

What this means for your decisions

  • The risk question for an agent is “what can it touch, and what can it do without asking?”, not “how clever is it?”
  • Start with read-only and ask-first. Widen permissions for specific, reversible actions.
  • An agent that reads content from outside (web pages, emails, documents) can be steered by instructions hidden in that content. Limit what it can do after reading untrusted material.
The detail your technical team handles optional

Tool definitions and connectors

Each tool is described to the model in a short definition: its name, what it does and what information it needs. Connectors are ready-made sets of tools for a particular system, such as a calendar or a document store. Your team chooses which to install and what account each one acts as.

Sandboxes

A sandbox is a sealed-off environment in which an agent can run commands without being able to reach anything else. It limits the damage a mistake can do.

Audit logs

A well-run agent records every tool it used, with what inputs and what came back. This is what lets you answer “what did it do, and why?” afterwards.

Prompt injection

A model cannot reliably tell the difference between instructions from you and instructions that appear inside material it is reading. Someone can therefore plant text in a web page, email or document that tells the agent to do something you did not ask for. This is called prompt injection, and the main defence is limiting what the agent is permitted to do, not hoping it will notice.

Human in the loop, human on the loop

“Human in the loop” means a person approves each significant action before it happens. “Human on the loop” means the agent acts by itself while a person monitors and can step in. The second is faster and carries more risk.
