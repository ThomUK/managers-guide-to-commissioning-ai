Hardware and performance

You need this if you are shown a hardware quote, or told a system will be “too slow”.

Relies on module 6 (a model must fit in memory) and module 7 (reading the prompt, then writing token by token).

The key idea

Three things decide performance. Memory capacity decides whether a model fits. Memory bandwidth decides how fast it writes. The processor decides how fast it reads, and how many people it can serve at once.

How big is the tank, how wide is the pipe

Memory capacity is the size of the tank: it decides whether the model fits at all. Memory bandwidth is the width of the pipe between memory and the processor. Every token the model writes needs one full sweep of its weights through that pipe, so a wider pipe means more tokens per second. A machine with a big tank and a narrow pipe can run a large model, but slowly.

The picture stops being true in one respect: nothing drains. The weights stay in memory and are read, over and over.

Why a GPU beats a CPU

A GPU has a great many small workers calculating at the same time, fed by memory with a very wide pipe. A CPU has a few powerful workers and ordinary memory, whose bandwidth is typically tens of GB/s against hundreds or thousands for the machines here. The number of workers also sets how fast a prompt is read. This is why AI hardware is described by its GPUs and their memory, and hardly at all by the CPU beside them.

Sharing the sweep

One sweep of the weights can produce a token for many users at once. This is batching. Each user’s speed drops a little, and total output rises several-fold, so serving many people is far more efficient than the single-user speed suggests.

The larger rungs also bring costs beyond the purchase: power, cooling and somewhere to put the machine.

What this means for your decisions

  • Ask of any hardware proposal: what model will it run, for how many people at once, at what speed? A price alone tells you little.
  • Small machines are for individuals and small teams and for sensitive work that must stay on site. Large machines only make sense when they are kept busy.
  • Above desk scale, you are also buying a power supply, cooling and somewhere to put it.
The detail your technical team handles optional

Bandwidth for each rung

  • Desk-sized AI computer: 273 GB/s.
  • Two desk-sized units, linked: 273 GB/s each. Linking adds capacity; it does not widen either pipe.
  • Deskside workstation: 7.1 TB/s for its 252 GB of GPU memory; 396 GB/s for the rest.
  • Rack server, 8 × H200: 4.8 TB/s per GPU.
  • Rack server, 8 × B300: up to 8 TB/s per GPU.
  • A CPU with ordinary memory: tens of GB/s, as a typical order of magnitude. No sourced figure is used.

Links between GPUs

When a model is split across several GPUs, they exchange data for every token. Slow links between them become the new narrow pipe, which is why multi-GPU servers are built with very fast connections.

Two speeds, two questions

Time to first token is mostly a question of computing power. Tokens per second for one user is mostly a question of bandwidth. A machine can be good at one and poor at the other.

Why benchmarks are hard to compare

A published speed depends on the model, the precision it was stored at, the software used to run it and the number of simultaneous users. Two figures for the same machine can differ several-fold for these reasons alone. The estimate in the picture above is capped at “100+” because, at high speeds, other limits take over from bandwidth.

The top rung

No published inference benchmark for an 8 × B300 server was found. The nearest evidence is a comparison of 8 × H200 against 8 × B200; B300 is the newer generation, with more memory.
