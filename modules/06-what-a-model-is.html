What a model physically is

You need this if someone tells you a model “won’t fit” or “needs a bigger GPU”.

The key idea

A model is a very large file of numbers. To run it, the whole file has to sit in fast memory. Its size decides what hardware can run it at all.

Parameters

What a model learned in training is held in its parameters, also called weights: billions of numbers. Model names usually say how many. “27B” means 27 billion. Bigger models are generally more capable, and they are always more demanding to run.

The file must sit in memory

Stored on disk, a model is one very large file. To run it, the whole file is loaded into fast memory beside the processor that does the calculations, usually a GPU.

A rough size is easy to work out. Each parameter is normally stored as a 16-bit number, which takes two bytes, so a model needs about two gigabytes (GB) for every billion parameters. A 27B model is about 54 GB.

If the file does not fit, the model does not run slowly. It does not run in any usable way. That makes memory capacity a pass or fail test, and it is the first thing a technical team checks.

The file can be shrunk. Quantisation stores each number in fewer bits, 8 or 4 in place of 16, so a model that did not fit may then fit, at some cost in quality. Try it in the picture; module 10 explains the trade.

An ordinary office computer fails the memory test for all but the smallest models. It has perhaps 32 GB of memory, and it is ordinary memory, not GPU memory, so even a model that fits writes slowly (module 8). A single desk-sized AI computer, the first rung of the ladder, is in practice the entry point for running useful models yourself.

At the other end are the leading hosted models. Their makers do not publish sizes, so the last option in the picture is an assumption. At that scale, stored at 16 bits, one copy is too big for the largest machine on the ladder, and a vendor runs many copies at once. That is why those models live in data centres, not offices.

Room left over

Fitting exactly is not enough. On top of the model, each conversation needs working space for the model’s notes on what it has read so far (module 7). That space grows with the length of each conversation and with the number of people using the model at once. As a rule of thumb, this course allows an extra 15%. A model that fits only without that margin is marked “tight”: it will load, but long conversations or several users may not.

What this means for your decisions

  • “Which model?” and “which hardware?” are one question, not two.
  • Memory capacity is a pass/fail gate. Speed comes later (module 8).
  • If you are told a model “won’t fit”, the choices are a bigger machine, a smaller model, or the same model stored less precisely (module 10).
The detail your technical team handles optional

BF16 and quantised formats

Engineers call the usual 16-bit storage format BF16 (or FP16). Compressing those 16-bit numbers into smaller ones gives the quantised versions, with labels such as 8-bit, 4-bit, Q4 or FP8. Module 10 covers them.

Why GPU memory specifically

The numbers have to be in memory the GPU can read directly and very quickly. A computer’s ordinary memory is usually separate from its GPU’s memory, and far slower to reach from the GPU, so having plenty of ordinary memory does not help much.

Unified memory

Some machines, including the desk-sized one on the ladder, have a single pool of memory shared by the CPU and the GPU. That makes a large capacity affordable, at the cost of lower speed than dedicated GPU memory. The deskside workstation has both kinds: 252 GB of fast GPU memory and a further 496 GB of slower memory.

Splitting a model across GPUs

A model too big for one GPU can be divided across several, which is how the rack servers reach their totals: eight GPUs of 141 GB or 288 GB each. The software has to manage the split, and the GPUs need fast links between them.

Headroom for context

The 15% margin used here is a teaching rule of thumb. The real requirement depends on the length of the context window in use and the number of simultaneous conversations, and for heavy use it can be much more.
