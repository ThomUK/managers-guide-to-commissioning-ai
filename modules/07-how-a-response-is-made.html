How a response gets made

You need this if you want to understand why AI sometimes pauses before answering, and why long conversations cost more.

Relies on module 1 (text is handled as tokens) and module 6 (a model is a block of numbers held in memory).

The key idea

A response has two phases. First the model reads your whole prompt in one go (fast). Then it writes the answer one token at a time (slower). It keeps notes on what it has read, the KV cache, so it never has to re-read.

Two phases, two numbers

When you send a prompt, the model first reads all of it. This phase, prompt processing, handles every token of the prompt together. Then comes token generation: the model writes its answer one token after another, and each new token needs a full pass through the model’s weights.

You feel these as two different numbers. Time to first token is the wait before anything appears. Tokens per second is how fast the answer then arrives. On one desk-sized machine, a 27-billion-parameter model read prompts at about 1,900 tokens per second and wrote at about 8 (S24). At those speeds a 4,000-token document is read in about two seconds, while a 500-token answer takes about a minute.

What limits each phase

Reading is done in parallel, so it is limited by raw computing power: how many calculations the processor can do at once. Writing is one token after another, so it is limited by how quickly the weights can be read out of memory, again and again. Module 8 builds on this difference.

The notes: the KV cache

As it reads, the model keeps notes on every token. These notes are the KV cache, and they mean the model never has to re-read the conversation for each new token. Switch the cache off in the picture to see what that saves.

The notes take memory, and they grow with the length of the conversation. When a provider can reuse the notes for a prompt it has seen before, that is prompt caching, and it is why cached input is priced lower.

What this means for your decisions

  • Long documents and long conversations cost more and need more memory, even if the answer is short.
  • “It’s slow” has two different causes. Ask which: slow to start, or slow to write.
  • Agents (module 3) re-send a growing conversation at every step, so caching matters a great deal for their cost.
The detail your technical team handles optional

What K and V stand for

K and V are “keys” and “values”, two sets of numbers that the model’s attention mechanism calculates for every token it reads. Later tokens are compared against the stored keys to decide which earlier values matter, which is why keeping them saves recalculating the whole conversation.

Prefill and decode

Engineers call prompt processing “prefill” and token generation “decode”. A benchmark that reports only one of the two speeds tells half the story.

How cache memory scales

The cache holds an entry for every token of every conversation in progress. Its size therefore scales with the length of the context in use and with the number of simultaneous conversations. For a busy service it can rival the size of the model itself.

The context window as a memory limit

A model has a maximum context window it was built for, but the practical limit on a given machine is often lower, set by how much memory is left for the cache once the model is loaded.
