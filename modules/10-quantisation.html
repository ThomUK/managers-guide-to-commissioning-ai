Quantisation

You need this if you are told a model has been “quantised” or see labels like “4-bit”, “Q4”, “FP8”.

Relies on module 6 (a model must fit in memory) and module 8 (what flows through the pipe sets the speed).

The key idea

Quantisation stores each of the model’s numbers less precisely. The model gets smaller and faster, at a small cost in quality. It is how large models are made to fit on modest hardware.

Fewer bits per number

A bit is one yes-or-no of storage. Each of a model’s numbers is normally stored in 16 bits. Quantisation stores each one in fewer, commonly 8 or 4. Halving the bits halves the size of the model, and roughly halves what must flow through the pipe for each token, so the model both fits on smaller hardware and writes faster.

What it costs

Generally, an 8-bit model is close to indistinguishable from the original, 4-bit is the common practical choice, and below that quality falls away quickly. These are tendencies, not guarantees.

The picture of the pattern helps, up to a point. A coarsened picture looks coarse. A coarsened model can stay fluent while getting subtle things wrong, so the loss has to be measured, not judged by eye.

For one 27-billion-parameter model, the 8-bit file was about 29 GB and a 4-bit file about 17 GB (S24). Real files run a little larger than the simple sum suggests. With 16 people using it at once, the 4-bit version produced about 134 tokens per second in total, against about 104 for 8-bit (S26).

Who decides

Quantisation is done once, to the model file, before the model is used. Many open models are published in several precisions. Which one to run is the technical team’s choice to make, and to test.

The same model at a lower precision is still the same model. It has the same knowledge and the same limits, held a little less exactly. That is why quantisation is usually tried before stepping down to a smaller model.

What this means for your decisions

  • “Can we run model X on machine Y?” often has the answer “yes, at 4-bit”. Ask what was given up and how it was tested.
  • A quantised large model usually beats an unquantised small one of the same file size, but this needs checking on your own tasks.
The detail your technical team handles optional

Formats an engineer will mention

  • FP8: each number stored as an 8-bit floating-point value.
  • NVFP4: a 4-bit floating-point format designed for recent NVIDIA GPUs.
  • GGUF Q4: a 4-bit version of a model in GGUF, a widely used file format for running models on small machines.
  • AWQ: a method for choosing how to round, usually to 4 bits, that protects the numbers that matter most.
  • INT4: each number stored as a 4-bit whole number.

Why some hardware prefers some formats

A processor is fastest with number formats it was built to calculate with directly. A format the hardware does not support natively has to be converted as it runs, which loses some of the speed gain. This is why the best choice of format depends on the machine.

Quantising the KV cache

The model’s notes on a conversation, the KV cache, can also be stored less precisely. This leaves room for longer conversations or more simultaneous users, with its own small effect on quality.

Evaluation before and after

The honest way to choose a precision is to run the same set of realistic test questions against each version and compare the answers. Published claims of “no loss” are usually averages over general benchmarks, and may not hold for a specialised task.

Why real files are larger than the sum

Some parts of a model are usually kept at higher precision because they are sensitive to rounding, and the file carries some extra information. The 4-bit file in the measured example averages about 5 bits per number.
