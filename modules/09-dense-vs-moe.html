Dense vs. MoE models

You need this if you see a model described like “35B-A3B” or hear “mixture of experts”.

Relies on module 8: each token written needs the model’s weights to flow from memory to the processor once.

The key idea

A dense model uses all of its numbers for every token. A mixture-of-experts (MoE) model keeps many specialist groups and consults only a few for each token. It still has to fit in memory in full, but it writes much faster.

Two sizes, two jobs

A dense model has one size. An MoE model has two. Its total parameters decide whether it fits in memory (module 6), because every expert has to be loaded and ready. Its active parameters, the ones used for any single token, decide how fast it writes (module 8).

Model names often carry both. “35B-A3B” means 35 billion parameters in total, of which about 3 billion are active for each token. Where a name gives only one number it is usually the total, so it is worth asking for the other.

What it buys

On the same desk-sized machine, a dense 27-billion-parameter model wrote about 8 tokens per second (S24). An MoE model with 35 billion parameters in total and about 3 billion active wrote about 30 (S25). The two are different models measured at different precisions, so this shows the direction, not an exact ratio. MoE is how many large current models reach a usable speed.

The trade

The speed is not free. An MoE model is generally less capable than a dense model of the same total size, but far more capable than a dense model of its active size. That is a tendency, not a rule.

One way to picture it: a hospital with every specialist on site, where each patient sees only the two or three they need. The whole building must be staffed, but each visit is quick. The picture breaks down in one place: a model’s experts are not tidy, human-style specialisms. Nobody assigns them subjects, and they cannot be read off like a staff list.

What this means for your decisions

  • Two models with similar “size” can differ several-fold in speed on the same hardware. Ask whether a model is dense or MoE, and its active size.
  • MoE helps speed, not fit. It does not let a model run on a smaller machine.
The detail your technical team handles optional

Routers and top-k selection

Inside each layer of an MoE model, a small component called a router scores every expert for the current token and passes the work to the highest-scoring few. “Top-k” is the engineers’ name for “the best k of them”. Parts of the model outside the expert blocks are still used for every token.

Why all experts must stay loaded

The router chooses afresh for every token, and the choice cannot be known in advance. Any expert may be needed next, so all of them have to sit in fast memory all the time.

MoE and batching

When many users share a sweep (batching), their tokens call on different experts, so more of the model is read on each sweep. The speed advantage of MoE over dense therefore narrows somewhat under heavy shared use.

How firm is the capability claim?

The comparison of MoE and dense capability is a general tendency seen across model families. It varies with how each model was trained, so teams compare specific models on their own tasks.
